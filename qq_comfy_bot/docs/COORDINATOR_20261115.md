# 调度与状态提交增量（2026-11-15）

## 已接入的实现

TaskCoordinator 提供五个执行车道：控制命令并发 4、文字回复并发 4、后台绘图规划并发 2、GPU 沿用单槽优先队列、状态提交为不跨 await 的同步事务。前三条异步车道各最多 64 个等待者，等待超时 120 秒；取消、异常都会释放计数和资源。GPU 保持原有优先级与有界等待。自动候选和明确索图补全均经过后台车道，包含定时主动分享的调用。控制与文字仍遵守原会话发送顺序及取消规则，不会强行撤回已交给传输层的消息。

StateCommitter 接管 Bot 会话存储入口，沿用 SQLite 三方版本合并。正文回执必须属于当前 pending_turn；未知或重复回执不能触发情绪提交；过期场景版本不能覆盖更新后的场景。已确认回复的情绪增量通过同会话事务内的 pending_affect 待办持久化，使用 Life 的事件幂等账本补交，启动时恢复。

语气检查只针对明确的直接贬低表达，保留普通不同意见与引用；触发时进行一次正文修复，不采纳修复模型的状态、记忆或图像授权。模型修复仍含贬低时删除对应句子，必要时承认该句表达不当。这是有限护栏，不是完整语义评判器。

## 验证与边界

新增测试覆盖后台饱和不阻塞文本/控制、取消排队计数释放、容量拒绝、旧回执、未知/重复回执、情绪写入后崩溃重放以及引语与观点保留。修改过程中 400 项全量回归通过，情绪待办追加后 42 项相关测试通过；最终全量结果见本地交付说明。

针对 5 篇原问题文章进行了 50 轮独立真实模型测试，59 次模型请求，回复失败 0 次；没有 QQ 或 ComfyUI 网络调用。仍观察到未经证实的因果解释和叙述时间偏差，不能将无失败等同于聊天质量完全通过。

尚非总体架构全部完成：天气/资料刷新等独立长期服务仍沿用原生命周期管理；并非全部能力已改成统一 TaskSpec。状态入口统一并不等于所有数据库成为一个 ACID 事务：本次情绪使用可恢复待办，用户事实与关系数据仍分别持久化。图片任务文件沿用原账本。尚未完成全部领域版本向量、百轮连续长期回归或真实 QQ/出图验收。默认不重启生产服务，不改角色、数据库、工作流或密钥。
